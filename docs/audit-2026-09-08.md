# Design audit - 2026-09-08

## Assessment

The layered architecture is appropriate for this ADL autonomy task. The previous documents were not a reliable implementation contract: they contradicted the current prompt, included a syntactically invalid skill YAML, and made unsupported runtime/safety claims. This audit replaces the conflicting definitions with a smaller fixed vocabulary and checkable artifacts.

Scope reviewed: every design document 00-13, the machine-readable skill library, foundation implementation plan, empty root files and local coding-agent settings. Driver/cuRobo facts were checked at immutable source revisions through the connected GitHub app. Astra was checked against official OpenAI documentation. There was no Git repository metadata in this workspace during the audit.

## Reviewable outputs

The catalog now has eight physical skills. observe has no hidden arm repositioning; set_gripper is empty-only; release requires support; stop/hold/confirmation are supervisor operations. Handler status is explicitly planned, and adding a catalog entry does not implement it.

The exact plan schema is generated from typed skill arguments. Model plans cannot add resource claims, arbitrary code/predicates, safety thresholds or retry rules. Four plan/context fixtures cover the nominal cabinet/bottle traces plus cabinet re-observation/resume. Documentation links to actual IDL/schema sources rather than embedding competing versions.

The offline checker validates strict parsing, schema consistency, graph/reference integrity, constraint units/bounds, and links. Rejection tests exercise unknown/unavailable skills, model policy overrides, duplicate IDs/JSON keys, non-finite values, stale identities, cycles and invalid typed args. These are design checks, not runtime symbolic/kinematic/safety verification.
